**1. The town weighed your case, but nobody said so.**
- **What happened:** you never presented a case on its own; you nominated with one,
  twice: `nominate kiran #89` (seq 588) and `nominate lian #136` (seq 960). Every listener
  judged it (the `argument_stance` events, seq 568–585 and 945–956):
  - **#89:** Fenwick, Isolde, Dorian, Agnes and Lian accepted; Constance and Edda
    partly; Odette rejected.
  - **#136:** Agnes accepted; Constance, Odette and Dorian partly; Isolde and Edda
    rejected.

  You saw only the nominee's defence.
- **Why:** `_player_nomination` (`game/game_meeting.gd:173`) calls
  `_evaluate_deduction(..., false, "nomination")`. The `false` means "don't speak". Herald's
  `a846e886` (Nov 20, after your Nov 19 call) made the town answer aloud, but only for the
  `case <#>` step. `nominate X #N` kept the silent path. The GUI's nominate button uses the
  same function. Quill found the same independently.
- **Minor, same area:** after `nominate kiran #89`, the prompt still offered
  `case <case#>` (seq 613). A case-backed nomination doesn't count as having used the case.

**2. The defence option wasn't removed, but you can't see it.**
- **History:** `fa306ebf` (Nov 19, your option b) retired the bare `defend` and `accuse`
  commands. Their replacement is `case <case#>`: lay a filed case about the nominee before
  the town. It defends them when its conclusion clears them (`case_direction`,
  `game_meeting.gd:215`).
- **Why it never showed for Dorian or Constance:** it's offered only at the "Your turn"
  step (`game_meeting.gd:494–501`), and only when a filed case names the nominee. You had
  filed only #89 and #136. The opening nomination prompt never lists it.
- **Stale help:** `game/game_screens.gd:51` still lists `defend [card#] | accuse [card#]`
  (Herald).
- **Question for you:** is a filed case meant to be the only way to speak for a nominee?
  There's no lighter "I vouch for them" without building a case first.

**3. The summary can't see guesses made in the daily guess window.**
- **Two stores:** the window (`ui/daily_guess.gd`, `apply` at 119–140) keeps its picks in
  its own node, never writes to the game's guesses (`g.guesses`), and logs nothing.
  - The grimoire reveal reads the window (`ui/main.gd:236`).
  - The outcome text, the case summary and the theory label read `g.guesses`

- **What the log shows:** only the typed `guess` commands. The summary's Demon guess
  (Lian) and Minion guesses (Dorian, Odette) came from those (seq 931–937). Anything picked
  only in the window couldn't reach it, and can't be checked from the log.
- **Unresolved:** a lost guess, at seq 558.
  - **What happened:** the guesses record Isolde as the Demon without any command for it.
    That also knocked your Demon guess on Kiran down to "?". Then
    `guess isolde breathstealer` (seq 560) left you with no Demon guess at all.
  - **Not the text command:** a probe at `f6f0ae58` shows `guess isolde breathstealer`
    leaves Kiran's guess alone. So the write came from the GUI, most likely the profile
    panel's role menu (`ui/profile_panel.gd:143`). The log can't show whether that was a
    click.
  - **Intended:** a new Demon guess replaces the old one, and so does a second guess at
    the same Minion gift (Odette as Breathstealer replaced Isolde, seq 937).

**1. The roster.**
- **When it happens:** a `search` ends the phase (seq 371 on day 2; seq 801 on day 3). The
  screen then holds the old phase while you read the trace.
- **Cause:** `ui/main.gd` runs the command first, so the world is already in the next
  phase. Only then does it freeze the townsfolk list (`main.gd:536`), and `freeze()`
  (`ui/cast_list.gd:159`) snapshots the new positions. The clock still shows the old phase.
- **Measured:** a probe confirms it (the clock held at the morning, and all 7 held lines
  matched the afternoon's).
- **Not a leak:** the phase has already turned, nothing can happen in between, and the
  lines match what the next overview shows. The same flaw affects the hold after a talk
  runs out of questions.
- **Fix:** freeze before the command runs.
- **Tests miss it:** `tools/test_control_flow.gd:197` checks that the list is frozen, not
  what it holds.

**2. Lian's night report changed after it was written down.**
- **What was recorded:** her night-1 fabrication was "I watched the Square: I saw Kiran out"
  (seq 346).
- **What she told the town:** "I watched Chapel Hill" (seq 464).
- **Cause:** `sim/evil.gd:208–211`. While scoring each evil player as a candidate to plant
  the night's frame, it rewrites a Night Watch bluffer's untold report in place to the
  death block. It does this *before* choosing anyone. Dorian won the slot (seq 349), but
  Lian's report had already been changed.
- **Why the grimoire is stale:** the rewrite isn't logged, so `grimoire lies`
  (`game/game_screens.gd:354`) still shows the old version.

**3. Dorian's "first night" was right.**
- **When it was made:** night 1. It was held that night (seq 345) and released on night 2
  (seq 717), still for night 1. "On the first night" is correct (`C.spoken_night`,
  `sim/content.gd:45`).
- **The bug:** `grimoire lies` (`game_screens.gd:360–363`) prints the night the lie was
  logged, not the night it's about. That's why both say N2.
- **What made it look impossible:** the gift descriptions' "not the first". See the
  observations below.

**4. A Monitor bluffer told a window sighting no Monitor can have.**
- **The rule:** a Monitor never gets window sightings (`sim/roles/monitor.gd:5`, `:18`),
  and the night engine enforces it for real and bluffing Monitors alike
  (`sim/world_night.gd:293`).
- **The planted frame:** #68 ("From my window, I saw Kiran out", seq 380) came from the
  evil plan. Its window branch (`evil.gd:202–203`) never checks the bluff, so Dorian got a
  window frame. The Monitor filter (`monitor.gd:166–171`) keys on a *claimed* role, and
  Dorian had only hinted by then.
- **It contradicts his own later claim:** "no one walked by my house" is for the same
  night, on the same block.
- **#67 ("I saw Edda go in") is true:** it comes from the neighbour mechanic
  (`world_night.gd:305–313`), which has no Monitor check either. That's a lesser
  inconsistency.
- **The missing lie: confirmed.** The planted sighting is stored as a plan (`evil.gd:230`),
  and `fake_night_sighting` (`evil.gd:1126`) returns it without logging a lie. So `grimoire
  lies` lists only the public accusation (seq 505), not the private telling (seq 380).
  Odette's planted sighting of Constance has the same gap.
- **Your read is right:** it's a logic bug, not an intended tell.

**5. A block reading names nobody.**
- **The card:** a Surveyor reading stores only the block, so card #76 has no subjects
  (`game/workshop_bridge.gd:205`).
- **What fails:** presenting it found no one (seq 769: "the card isn't about anyone
  living"). Lian's about-me check missed her too (seq 782, `sim/mind_press.gd:80–87`).
  `CardModel.about` also ignores block readings.
- **The NPCs disagree:** Kiran (seq 456) and Lian (seq 666) both treat the reading as being
  about the Market's residents.
- **Your read is right:** it should resolve to them (Agnes and Lian).

**6. `ask are rumormonger` was a right guess, not a wrong one.**
- **Why:** Rumormonger was Odette's bluff, so she treats it as correct (seq 80). A right
  guess at the hint stage replays the hint and spends the question
  (`sim/social_approaches.gd:304–331`). The bespoke wrong-guess line never applied.
- **What is a problem:** the repeat adds nothing. It also tells right from wrong: a wrong
  guess gets "I'll keep to myself" instead (Dorian, seq 394). The function's own comment
  says a guess never rules anyone out.
- **Question for you:** what should a right guess at the hint stage get?
