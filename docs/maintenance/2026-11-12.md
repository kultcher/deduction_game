## A. Code review

Ranked by severity. No correctness bugs were confirmed.

**A1. The sweep can't run the pre-Phase-5 bot (tools, medium).** `tools/autoplay.gd` header
says `--no-crosscheck` and `--no-declare` "give the earlier bot, for paired sweep cells", and
`_mode_name()` names those cells `bot_nocross` / `bot_nodeclare`. But
`tools/sweep_shard.py:199` only accepts `passive`, `bot`, `bot_pre_m4`, `no_present`,
`present_vote`, and its command builder (`sweep_shard.py:110-116`) never passes the new
flags. Scenario: Michael dispatches a sweep to measure what Phase 5 adds; the `bot` cell
now runs the Phase 5 bot and there is no cell for the earlier one, so the comparison has
to be against the `12cd656` sweep, which also differs by #136. Suggested fix (code, not
made): add `bot_nocross` and `bot_nodeclare` (or a `flags` field per cell) to
`sweep_shard.py` and the workflow's `costs` table.

**A2. The silent cell declares (design question).** `autoplay._decide_inner` returns
`_declaration_command()` at the meeting before the no-present branch, and `_silence()`
(`tools/autoplay.gd:638`) only drops `present`, `convince` and `tell`. So the `no_present`
cell now makes a public declaration that changes every NPC's movement model. Whether a
declaration counts as "presenting" is your call; if it should be silent, `_silence` would
drop `declare ` commands in the meeting too.

**A3. Night Watch keyed by role id in the sighter contests (design rule, low).**
`workshop/live_activity.gd` `_sighting_contests` and `alt_of` treat a report as a sighting
only when `role == "nightwatch"` and the reading carries `data.seen`. It's correct for
today's roster, but it's a per-role check: a future gift whose reading names people seen
at night would be left out of the contests. Keying on the reading's shape (`data.seen`
present) or a `C.ROLES` flag, as `night_walk` does, would follow the general-mechanics rule.
The bot's cross-check partners (`tools/analyst.gd` `GROUP_ROLES` and the `lamplighter`
partner) are also role lists, but they're bot tooling, not game logic.

**A4. `test_phase5_bot` runs on `main` only (info).** It isn't in
`tools/ci_fast_suites.txt`, so pull requests don't run it; `main` runs every suite. The
other three new suites (`test_framed_defence`, `test_sighter_contest`,
`test_gravedigger_bluff`) were added to the fast list.

Checked and found consistent:
- **Sighter contests (#135):** the GDScript packing in `_ensure_factor_handle` matches
  `LiveActivityKernel.AttachContests` (subset order m = 1..2^k-1, converted flags per
