## A. Code review

Ranked by severity. No correctness bugs were confirmed in game code. Line numbers are on
`eece565`.

1. **Low (tools): the sweep workflow accepts a cell that its shard script then rejects.**
   `.github/workflows/balance-sweep.yml` strips `_nodeclare` / `_nocross` from any mode
   before validating, so `{"mode": "passive_nocross"}` passes the plan job. But
   `tools/sweep_shard.py:222` (`split_mode`) raises "bad mode" for flags on `passive`.
   Scenario: someone dispatches that cell; every shard job of it fails after the runners
   have built the game. Suggested fix: in the plan step, reject the suffixes when the base
   is `passive`, matching `split_mode`.
2. **Note, intended: Workshop listeners lose their working theory when connections is on.**
   `workshop/jury.gd:960` skips the persistence (Theory bias) path when the connections
   result is present. The comment and the handoff log say so (Codex, #141). Only matters
   once the switch is turned on for play; worth keeping in the step list.
3. **Checked and fine:** the content-only holds mask (`RoleConstraints.cs` `FlagContentOnly`,
   `solver.gd:1704-1740`) is keyed by `graded_rule` in the question cache, so switching the
   rule can't reuse a stale mask. The core memory in `workshop_ownership.gd:151-158` is only
   written by the applied refresh and carried in the cached input, so a refresh with
   nothing new is still a cache hit. `mind_dialogue.gd:849` calls `_honest_outing` twice,
   but it is memoised per night and day, so both calls agree.

Could not verify: whether the Sleepwalker self-doubt in `CaseEval._class_fits`
