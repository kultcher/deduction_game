## A. Code review

1. **The nightly full run can be cancelled (medium-low, CI, #221).** `.github/workflows/ci.yml:26-28`

   run that queues behind a push run is the one pending run of that group, so the next merge
   replaces it. That is the "a newer run hides the red one" problem the nightly run was
   added to fix. Suggested fix: `group: ci-${{ github.event_name }}-${{ github.ref }}`.

- **Per-role special cases.** New: `_reading_group` (#249) hard-codes "medium",
  "surveyor" and "chronicler" (`sim/mind_meeting.gd:1740-1751`), which belongs in a
  `RoleDef` hook. Still there: `fabrication_check.gd`'s role lists. These are tied to how one
  gift works and are your decisions, so they're notes, not breaches: `_route_trusted`
  (Warden, `case_eval.gd:1260`), `_list_broken` (Night Watch, `:1281`), "nightwatch" in
  `source_doubt.gd:473`, and the Registrar night-0 exception in `source_doubt.gd`.
- **Constants outside `tuning.gd`:** `DEMON_CROWD` (Needs Michael 4).
- **Modern words and night numbers in spoken text:** none in new spoken lines. Night
  numbers are on cards and panels (Needs Michael 5). One latent case:
  `sim/dialogue_presentations.gd:163` would speak the raw note "Seen elsewhere: X's sighting
  on night N" if a voice lacked its key (all 15 have it). `sim/roles/veteran.gd:46` "the
  Demon came for me on night %d" is first person. Check whether it's ever spoken.
- **Every lie has a logged reason:** yes for every new path (Clerk blend, Martyr and
  Executor bluffs, released held readings, "my gift may have been turned"). The reasons'
  *wording* in the reveal is A4.
- **Determinism:** no unseeded randomness. New draws use `w.rng` / `w.chance` /
  `decision_roll`, and iteration is over arrays.
- **Sim separate from presentation:** nothing under `sim/` references `ui/` or `game/`.
  The UI PRs (#322, #323, #226) only read state. The withdraw command (A2) is in `game/`
  and changes beliefs, which is a state bug rather than a layering one.
- **NPCs as perfect solvers:** the new evil behaviour (blend or disrupt, frame memory,
  "too clean") uses team knowledge and public heat, not solver output. Nothing new leans
  toward a perfect solver beyond what you set.
