## A. Code review

Ranked by severity. Each one comes from reading the code and was not reproduced in the game.

1. **Low-medium. The stage button says "Done" while the town is still speaking.**
   `ui/courtroom_stage.gd:356` sets the button to "Continue" only if another speech is already
   queued (`waiting() > 0`). Since #101, `ui/main.gd:817` works out at most one speaker ahead, and
   only once nobody is waiting. So when a speaker comes forward the queue is empty, the button says
   "Done", and when the next speaker is queued a moment later, `push()` (`ui/courtroom_stage.gd:233`)
   doesn't touch the label because someone is already on stage.
   *Scenario:* a meeting with six speakers. Each of them shows "Done" under their line; only the
   action-pane "Continue" is right. *Suggested fix:* in `push()`, when `current` is not empty, set
   the label again from `waiting()`; or let main tell the stage that the meeting is still streaming
   and show "Continue" until it isn't. A check in `test_meeting_stage` or `test_control_flow` would
   catch it.

2. **Low. A higher-weight bare defence replaces a grounded one on the same reading, and with it
   the graded test.** `workshop/shared_ledger.gd:155–159` keeps one challenge per reading, the one
   heard most strongly, and now marks it `bare` from that one entry's grounds. Keeping the strongest
   was already the rule (its supports were already dropped), but now a stronger bare objection also
   turns off grading that the weaker grounded one would have had. This can't happen today, since NPC
   defences never have grounds (Needs Michael 2). It matters only if NPC defences start citing
   grounds. *Suggested fix, if that happens:* mark `bare` only when no challenge on the reading has
   grounds, or merge grounds across entries.
